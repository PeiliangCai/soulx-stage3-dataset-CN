# Execution Approval Protocol

本文件约束本项目中 AI 助手的执行行为，避免未经项目负责人确认就改变代码、数据、环境、训练方法或评测方法。

## 1. 适用范围

以下行为开始前必须先提交执行方案，并等待项目负责人明确确认：

- 创建、修改、移动或删除文件与目录；
- 修改代码、配置、数据、软链接、Git 状态或运行环境；
- 下载代码、模型、数据或安装、升级、卸载依赖；
- 调用外部 API 或产生费用；
- 启动训练、评测、数据处理或其他长时间运行任务；
- 启动会占用 GPU、大量 CPU、内存或磁盘空间的进程；
- 改变已经确认的实验方法、数据划分、超参数、checkpoint 网格或评测口径。

## 2. 执行前必须说明的内容

执行方案至少包含：

1. 本次执行的目标和明确边界；
2. 将创建、修改或删除的文件与目录；
3. 将运行的程序、训练入口和关键参数；
4. 相对官方代码或既有方案的全部差异与补丁；
5. 使用的数据、模型、环境和硬件；
6. 预计耗时、磁盘占用、GPU 占用及 API 费用；
7. 验证方法、产物位置、失败恢复方法和回滚边界；
8. 是否会影响或覆盖已有产物。

项目负责人明确确认后，只能执行已确认的范围。确认不能被解释为对未披露操作的授权。

## 3. 只读检查

- 为形成可靠方案而进行本地只读检查时，也应先向项目负责人说明检查目的和范围；
- 只读检查不得自动扩展为文件修改、依赖安装、网络访问、训练或评测；
- 检查发现需要改变已确认方案时，必须停止并重新提交方案。

## 4. 方案变化与重新确认

出现下列任一情况时必须暂停，说明实际情况并重新确认：

- 需要增加未披露的补丁、脚本、依赖、数据或模型；
- 训练流程、有效 batch、学习率、scheduler、数据采样或 step 语义发生变化；
- 预计耗时、磁盘占用或费用显著超过已确认值；
- 发现官方方法无法按原方案执行；
- 需要覆盖、删除或迁移已有产物；
- 验证结果与执行前假设冲突。

## 5. 官方代码隔离

- `third_party/SoulX-Duplug-upstream` 作为官方上游基准，只允许读取和 Git 完整性检查；
- 所有补丁必须应用到新的独立副本，不得直接修改官方上游目录；
- 派生副本必须记录官方基准 commit、修改文件、diff 和文件 SHA-256；
- 报告必须区分“官方未修改流程”“官方流程加补丁”和“自定义训练流程”。

## 6. 实验诚信

- 禁止依据 benchmark 结果反向修改训练标签、数据划分、评测样本、解码规则或指标实现；
- 禁止为了靠近论文结果选择性丢弃样本、checkpoint 或失败结果；
- 数据划分和评测规则必须在查看对应实验结果前冻结并记录身份哈希；
- 所有完整结果、失败、异常、提前停止及未测点都必须如实记录；
- 推断值必须标注依据和置信度，不得表述为已验证事实。

## 7. 完成后的报告义务

每个已批准阶段完成后必须报告：

- 实际执行的操作和命令类别；
- 实际创建、修改和删除的文件；
- 与批准方案是否一致；
- 测试、训练或评测结果；
- 产物路径和关键 SHA-256；
- 尚未执行的后续阶段；
- 任何需要项目负责人再次确认的决策。

## 8. 当前项目的额外约束

- SoulX Stage 3 官方发布权重不含 optimizer、scheduler、GradScaler 和 Trainer global step；只能进行模型权重续训，不能宣称精确恢复官方 optimizer 现场；
- 公开配置中的 `total_steps=1800` 只能作为起始 step 的低置信度估计；
- 续训练必须优先保留官方 Lightning `Trainer.fit()`、`training_step()`、`configure_optimizers()`、DataLoader 与梯度累积语义；
- 必要的 NaN、严格 checkpoint 加载、冻结会话级 split、审计日志和 checkpoint 补丁必须逐项披露；
- Table 3 benchmark 不得用于选择训练 LR、修改数据或调节评测规则。

## 9. 持久状态辅助与上下文恢复

- 当前对话和项目负责人的最新指令始终是任务方向的主要依据；磁盘持久状态用于辅助任务开展和恢复，不能替代对话，也不能覆盖更新的用户指令；
- 长任务、连接中断或上下文 compact 后，继续执行前必须先读取本文件、`project_state/ACTIVE_TASKS.md`、`project_state/active_tasks.json` 及其中引用的实时 run manifest；
- 必须同时检查登记的 `tmux` 会话和实际进程，不能仅凭对话记忆或静态 Markdown 判断任务是否仍在运行；
- run manifest 是运行进度的实时来源，任务账本只保存任务边界、依赖、入口和恢复路径；账本快照与实时 manifest 不一致时，以实时 manifest 为进度事实，并修正账本；
- 若磁盘状态与当前对话存在冲突，或无法判断哪条指令更新，必须暂停并向项目负责人确认；
- 每个长任务必须记录唯一 task ID、`tmux` 会话、批准范围、禁止动作、输入/输出、依赖、完成条件和失败恢复方式；
- 并行任务必须声明资源互斥。当前 Table 3 运行期间，DuplexConv 扩展只允许 metadata/方案/泄漏门禁等轻量准备，不得并行启动 Paraformer、GLM tokenizer、训练或其他 GPU 工作。
